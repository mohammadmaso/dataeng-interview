## به زبان ساده (مبتدی)
نگهبانی را تصور کنید با دفترچه‌ای خیلی کوچک که نمی‌تواند همه‌ی مهمان‌ها را فهرست کند ولی می‌تواند با اطمینان بگوید «این آدم قطعاً دعوت نشده» یا «شاید دعوت باشد، برو فهرست کامل را ببین.» گاهی کسی را که باید چک می‌شد رد می‌کند، اما هرگز مهمان واقعی را اشتباهاً رد نمی‌کند. Bloom filter همین پیش‌بررسی سریع و ارزان است.

## نحوه‌ی کار (متوسط)
Bloom filter آرایه‌ای از `m` بیت با `k` تابع hash است. برای افزودن عنصر `k` بیت ست می‌شود و برای پرس‌وجو همان بیت‌ها چک می‌شوند. اگر یکی ۰ باشد عنصر هرگز اضافه نشده؛ اگر همه ۱ باشند احتمالاً اضافه شده (عناصر دیگر ممکن است آن بیت‌ها را ست کرده باشند). حذف ندارد (counting Bloom filter یا cuckoo filter دارند) و با پر شدن false-positive بیشتر می‌شود؛ اندازه‌اش را از `n` مورد انتظار و نرخ هدف بسازید.

```
m bits, k hash functions
add("alice"):   set bits h1(x), h2(x), ..., hk(x)
query("bob"):   if any of those k bits is 0 -> definitely NOT in set
                if all are 1             -> maybe in set

false-positive rate ~ (1 - e^(-kn/m))^k
```

کاربردها: storeهای LSM (رد SSTableهایی که نمی‌توانند کلید را داشته باشند)، Bloom filter ستونی در Parquet/ORC برای point lookup، skip index در ClickHouse، runtime filter در join (حذف زودهنگام سطرهای probe)، پذیرش در cache و پیش‌بررسی dedup.

## نگاه سنیور و نکات مصاحبه
ارزش آن در اجتناب از lookup گران در مسیر منفی است: بیشتر خواندن‌های کلید ناموجود اصلاً به دیسک نمی‌رسند. مصالحه‌ها: حافظه در برابر نرخ false-positive (حدود ۱۰ بیت برای هر عنصر تقریباً ۱٪ می‌دهد)، عضویت دقیق نیست، شمارش یا حذف ندارد و برای شرط‌های بازه‌ای بی‌فایده است. فقط برای فیلتر برابری روی ستون پر cardinality مؤثر است که آمار min/max در آن شکست می‌خورد. در dedup استریمی، Bloom filter می‌تواند تکراری را حذف کند ولی ممکن است رویداد جدید را اشتباهاً حذف کند (false positive)، پس جایی که از دست رفتن قابل‌قبول نیست مناسب نیست.

سؤال مصاحبه: «Cassandra چطور در خواندن همه‌ی SSTableها را چک نمی‌کند؟» پاسخ: هر SSTable یک Bloom filter دارد؛ اگر بگوید کلید نیست فایل رد می‌شود و فقط فایل‌های محتمل خوانده می‌شوند؛ false positive فقط یک خواندن دیسک اضافه هزینه دارد.
