## به زبان ساده (مبتدی)
کتابخانه‌ای را تصور کنید که کتاب‌ها را بر اساس حرف اول در قفسه‌ها می‌چیند. برای کتابی که با «م» شروع می‌شود مستقیم به قفسه‌ی «م» می‌روید و کل کتابخانه را نمی‌گردید، و چند کتابدار می‌توانند هم‌زمان روی قفسه‌های مختلف کار کنند. پارتیشن‌بندی داده‌ی بزرگ را همین‌طور تقسیم می‌کند تا بخشی از کار حذف یا موازی شود.

## نحوه‌ی کار (متوسط)
این واژه در سه سطح استفاده می‌شود که در مصاحبه اغلب با هم قاطی می‌شوند:

- پارتیشن جدول/ذخیره‌سازی: یک دایرکتوری یا سگمنت برای هر مقدار (تاریخ، منطقه) تا کوئری‌های دارای فیلتر روی آن ستون بقیه را prune کنند. ستونی با cardinality متوسط انتخاب کنید؛ ریزتر یعنی فایل‌های ریز زیاد.
- پارتیشن پردازش: تکه‌ای از داده که یک task در Spark/Flink پردازش می‌کند؛ تعدادشان موازی‌سازی و حافظه‌ی هر task را تعیین می‌کند.
- پارتیشن استریم: پارتیشن topic در Kafka واحد ترتیب، موازی‌سازی و تخصیص به consumer است.

```
-- Table partitioning (pruning)
CREATE TABLE events (...) PARTITIONED BY (dt DATE);
SELECT count(*) FROM events WHERE dt = '2024-05-01'; -- reads 1 partition

# Kafka: key decides partition (ordering per key only)
partition = hash(key) % num_partitions

# Spark
df.repartition(200, "user_id")
```

پارتیشن با hash بار را یکنواخت پخش می‌کند ولی محلی‌بودن بازه را از دست می‌دهد؛ پارتیشن بازه‌ای ترتیب و range scan را نگه می‌دارد ولی ریسک نقطه‌ی داغ دارد (کلیدهای زمانی به آخرین پارتیشن فشار می‌آورند).

## نگاه سنیور و نکات مصاحبه
کلید پارتیشن خوب با فیلتر غالب جور است و پارتیشن‌هایی با اندازه‌ی مشابه و نسبتاً بزرگ می‌سازد. اشتباهات: پارتیشن با ستون پر cardinality مثل `user_id` (میلیون‌ها پارتیشن ریز)، skew، پارتیشن روی ستونی که کسی فیلتر نمی‌کند، و فراموش کردن اینکه تعداد پارتیشن Kafka را نمی‌شود راحت کم کرد و تغییرش نگاشت کلید به پارتیشن را به هم می‌زند. table formatهای مدرن hidden partitioning و partition evolution (در Iceberg) دارند تا کوئری‌ها نیازی به اشاره به ستون پارتیشن نداشته باشند.

سؤال مصاحبه: «برای جدول events چطور طرح پارتیشن انتخاب می‌کنی؟» پاسخ: بر اساس تاریخ رویداد (برای حجم خیلی زیاد ساعت) چون اغلب کوئری‌ها روی زمان فیلتر می‌کنند، اندازه‌ی فایل نزدیک هدف، sort داخل پارتیشن بر اساس فیلتر رایج دوم، و پرهیز از کلیدهای پر cardinality.
